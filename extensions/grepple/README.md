# Grepple workflow for Grip

A small Grip extension that favors Grepple through Bash. It does **not** register or override tools. It provides an opt-in `/grepple-install` command; loading the extension never downloads or installs a binary.

The independently versioned official package starts at `1.0.0` and supports Grip `>=0.3.0 <0.4.0`. It uses the current typed job-factory, workspace-backend and approved-host APIs rather than compatibility shims for older clients. Core version synchronization can extend the upper bound for later Grip releases. Tests validate this checkout and the packaged factory; compiled executable smoke tests and source/license approval remain required before publication. See the [official authoring guide](../README.md).

On session start (including reload, new, and resume), it deactivates `read`, `grep`, `edit`, `write`, and `grepple`, ensures `bash` is active, and leaves unrelated active tools untouched. Grip's built-in tools remain registered and can be re-enabled with `/tools`, except that `edit` calls are blocked while this extension is loaded. The extension registers a job factory that applies the same guidance, tool selection, and Grepple guard to jobs but does **not** register `/grepple-install` for them.
Before each agent run it adds brief Grepple guidance when Bash is active, unless a custom system prompt is in use. If loaded project instructions already include `## Grepple-first repository workflow`, it adds only a short reminder to apply observed, checksum-current metadata labels to broad local tree/search calls; otherwise it adds the full workflow prompt. In Grip's structured default prompt, this guidance stays under Guidelines, ahead of the Skills and Jobs catalogs and Grip documentation; with older or custom prompt layouts it falls back to appending without replacing other instructions. Missing/stale coverage or exhaustive audits still require an unfiltered pass. Metadata filters do not apply to graph, grit, architecture, or remote queries.

For Bash calls, the extension passes the proposed shell command to `grepple grep-guard` in the **active tool backend**, never the extension host. It checks `~/.local/bin` as well as the backend's PATH. The CLI's shell-aware classifier blocks legacy local-search commands such as `find`, `grep`, `egrep`, `fgrep`, `rg`, `ag`, `ack`, `fd`, `fdfind`, and `locate`, including supported wrappers; the denial uses the CLI's canonical reason. Append `# grep-guard:allow` only for a genuinely exceptional command. A missing/old CLI, a timeout, oversized input, or an invalid response **fails open**; this is a workflow guard, not a sandbox or security boundary.

## Usage

1. Load from a checkout with `grip -e extensions/grepple/index.ts`. Once published in the official catalog, install with `grip install official:grepple` or use `/extensions`.
2. Run `/grepple-install` explicitly to download the [official Grepple installer](https://github.com/greppleai/grepple/blob/main/install.sh) and install the latest checksum-verified release into `~/.local/bin` in the active tool backend. For a connected, mapped Grip sandbox, it installs there first and then asks for **fresh host approval** before installing separately on the host. Host approval expires after 60 seconds; command execution has its own 600-second limit. No automatic install or `sudo`; no shell profile changes. Review the installer before running it: its script comes from the repository's `main` branch and is executed in each environment. If host approval is denied or the host install fails, the sandbox installation remains. An unmapped sandbox (including arbitrary attached daemons without a mount mapping) or unrelated remote daemon cannot perform a two-sided install; the command refuses without installing. Without a sandbox, the local backend is the host and is installed once.
3. Add `~/.local/bin` to your PATH if needed for other shells; the extension's guard already checks it. Verify with `printf '%s' '{"command":"rg needle ."}' | ~/.local/bin/grepple grep-guard` and expect `"blocked":true`.
4. Run the focused tests with `node --import tsx --test extensions/grepple/test/*.test.mjs` from the Grip repository root. From `packages/coding-agent`, run `node ../../node_modules/vitest/dist/cli.js --run test/official-grepple-artifact.test.ts` to check deterministic packaging and isolated standalone-style parent/job factory loading. Both commands run in official validation and publication CI. Run `npm run check` from the repository root before merging.

Use Bash for `grepple overview`, `grepple tree --depth 1`, focused `grepple --at` reads, and `grepple write --root .` with a quoted literal heredoc. Use the current directives directly: `::grepple replace PATH START [END]`, `::grepple create PATH`, and `::grepple delete PATH SHA256`. For example, put one directive and its body in the shell heredoc; the next directive or EOF ends the body—there is no end marker or `::grepple end`. Obtain clean Grepple anchors before `replace`, and use the file's current SHA-256 for `delete`. Bash runs in Grip's active workspace backend; host installation is the only host-side action by this extension.
